# 質問への回答(RAG)の設計 案

原典:仕様書とIssue一覧(2026/10/11版)の「質問への回答(RAG)」とIssue 60〜68。
この文書は Issue 60 の案。チームのレビュー後に確定する。

## 方針
- 登録されたデータにあることだけを答え、根拠(自販機・価格・記録日)を必ず一緒に表示する
- AIに任せるのは「文章の数値化」と「条件に合う根拠の行の選択」だけ。回答の文章は、選ばれた根拠の行からサーバーで組み立てる
- 当てはまる商品の判定は索引(Vectorize)、価格の比較や台数はSQLで出し、AIには計算させない

## 検索の単位
- 商品1件を1つの文章にする(自販機単位ではない)
- 文章の作り方(Issue 62):`商品名 / メーカー / カテゴリ / 容量ml / 説明` をつなげる。空の項目は飛ばす
  - 例:`綾鷹 / コカ・コーラ / お茶 / 525ml / 無糖。苦みが少ない緑茶。カフェインあり`
- 価格や自販機は文章に入れない(変わるため。必ずDBから取る)

## 索引(Vectorize)
| 項目 | 値 |
|---|---|
| 索引名 | canmatch-products |
| 埋め込みモデル | @cf/baai/bge-m3(多言語対応) |
| 次元数 | 1,024 |
| 似ている度合いの測り方 | cosine(大きいほど似ている) |
| ベクトルのID | 商品ID(文字列。例 "12") |
| メタデータ | 持たない(検索結果の商品IDからDBをたどる) |

- 商品の追加・更新のときに登録する。同じ商品IDで登録し直すと上書きされる(増えない)
- 登録に失敗しても投稿は成功させ、あとで全件登録し直すコマンドで補う(Issue 63)

## 検索
- 上位10件を取り出す
- 1位の score がしきい値未満なら、飲み物と関係のない質問とみなして答えない(生成を呼ばない)
- しきい値以上なら、上位10件(score がしきい値未満のものは除く)を根拠の候補にする
- しきい値は仮に 0.45。Issue 67 の評価で調整する
  - 設定:`CF_RAG_SCORE_THRESHOLD`(しきい値)、`CF_RAG_TOP_K`(取り出す件数)、`CF_RAG_MAX_EVIDENCE`(AIに渡す最大行数)
  - 実装:`App\Services\Rag\EvidenceRetriever`(Issue 64)
  - 確認用:`php artisan rag:evidence "甘くない炭酸"` で、1位の score と根拠の行を表示する(生成は呼ばない)
  - 61 での確認(3件のみ):飲み物の質問は1位 0.60 前後、「明日の天気は」は1位 0.40
- score では「炭酸かどうか」のような話題は区別できるが、「甘くない」のような条件は区別できない。
  条件の判断は、根拠に商品の説明を含めて生成に任せる

## 根拠(AIに渡すデータ)
残った商品を扱う自販機の行を、SQLで取り出す。

条件:非表示の自販機は除く(Issue 10 の列ができたら)
並び順:価格の安い順
件数:最大 20 行(AIに渡す量を抑えるため。Issue 64 で調整)

1行の形:
| 項目 | 例 |
|---|---|
| machine_id | 3 |
| product_id | 12 |
| product_name | 綾鷹 |
| volume_ml | 525(不明なら null) |
| price | 160 |
| temperature | cold(不明なら null) |
| recorded_at | 2026-10-17(日本時間の日付) |
| days_ago | 0(日本時間の日付で数える) |
| description | 無糖。強い炭酸水(商品の説明。Issue 62で書く) |

## 回答の生成(Issue 65)
- 入力:質問と、根拠の一覧
- 出力:JSON `{ "citations": [{ "machine_id", "product_id", "price" }] }`
- 使うモデル:`@cf/google/gemma-4-26b-a4b-it`(`CF_GENERATION_MODEL`)。
  考える機能を止める(`CF_GENERATION_DISABLE_THINKING=true`)、JSONで返させる(`CF_GENERATION_JSON_MODE=true`)
- 予備:`@cf/mistralai/mistral-small-3.1-24b-instruct`。`CF_GENERATION_DISABLE_THINKING=false` にして使う
  (true のままだと HTTP 400 になる)
- モデルを変えたときは、Issue 67 の評価で、同じ質問で正しさを比べる
- AI に任せるのは「条件に合う根拠の行の選択」だけ。AI の文章は回答に使わない
- 回答は、固定の前置きと、選ばれた根拠の行(商品名・自販機・価格・日付)から、サーバーで組み立てる。
  行の順番は、AI が返した順ではなく、根拠の一覧の順(価格の安い順)にする
- サーバーで確かめること:citations の各行が、根拠の行(自販機ID・商品ID・価格の組)と完全に一致する
- 該当なしのときは、サーバーで決めた「登録されたデータからは条件に合う商品を確認できません。」を返す

## 答えない場合(生成を呼ばない)
次のときは「登録されたデータからは確認できません」と返す。
- しきい値を超える商品がない(飲み物と関係のない質問もここで落ちる)
- 商品はあるが、扱う自販機がすべて非表示
- 根拠が0行

## 失敗したとき
- 生成の失敗、無料枠切れ:AIによる絞り込みができないので、根拠の一覧(価格の安い順)をそのまま表示し、「条件での絞り込みができませんでした」と添える
- 数値化・検索の失敗:「いまは質問を受け付けられません」と表示する

## 質問ページ(Issue 66)
- URL:`/ask`(ログインが必要)。ナビの「質問」から開く
- 流れ:`App\Services\Rag\QuestionAnswerer` が、根拠を集め(64)、根拠があれば回答を作る(65)
- 表示:回答、根拠の一覧(自販機の詳細へのリンク、価格、温冷、何日前の情報か)、根拠の自販機の地図
- 回答が AI の選んだ内容であることと、価格が変わっている場合があることを表示する
- 状態ごとの表示
  | 状態 | 表示 |
  |---|---|
  | answered | 回答と、回答に使った根拠の行 |
  | no_match | 「登録されたデータからは条件に合う商品を確認できません。」 |
  | no_evidence | 「登録されたデータからは確認できません。」(生成を呼ばない) |
  | fallback | 「条件での絞り込みができませんでした。…」と、根拠の一覧(安い順) |
  | unavailable | 「いまは質問を受け付けられません。…」 |

## 記録と回数の上限(Issue 68)
- question_logs:質問文、取り出した商品ID、渡した根拠、AIが選んだ行、回答、処理時間、成否(列の定義は data-contract.md)
  - ある回答が、どの商品とどの自販機のデータから作られたかは、evidence と citations で追える
- 1人が1日に質問できる回数の上限:10 回(`CF_RAG_DAILY_LIMIT`)。日本時間の0時で区切る
  - Cloudflare を呼ぶ前に、利用者の行をロックして1回分の枠を確保する(question_logs に pending の行を作る)。同時に送られても上限を超えない
  - 上限に達したら、Cloudflare を呼ばずに「今日の質問は上限の10回に達しました」と表示する(記録も残さない)
  - 枠の確保に失敗したときも Cloudflare を呼ばない
  - 画面に「今日はあと N 回質問できます」と表示する
- 実装:`App\Services\Rag\QuestionDesk`(上限の確認と記録)→ `QuestionAnswerer`(回答)
- 無料枠を使い切ったとき(生成が HTTP 429):根拠の一覧(安い順)だけを表示し、「今日の AI の無料枠を使い切ったため、条件での絞り込みができませんでした」と添える
- 1日のニューロン使用量の確認方法:Cloudflare のダッシュボードの Workers AI の画面で、その日の使用量(ニューロン数)を見る。無料枠は1日 10,000 ニューロン
  - 発表前のリハーサルでは、質問を何回か試したあとに使用量を見て、1回あたりのおおよその量を記録しておく

## 類似度だけでは条件を守れない(Issue 61 の確認結果)
- 「甘くない炭酸」では、甘いコカ・コーラ(0.606)が無糖のウィルキンソン(0.594)より上になった
- 埋め込みは話題(炭酸)はとらえるが、否定(〜ない)や条件は区別できない
- そのため、根拠に商品の説明(description)を含め、条件に合うかは生成(Issue 65)で判断させる
- 条件を守れているかは、Issue 67 の評価で、否定や温冷の条件を含む質問を入れて確かめる

### AI の文章を回答に使わない理由(Issue 65 のレビューより)
- 回答の文章を検証で止める方式(正規表現で自販機・価格を探す)では、「価格→自販機」の語順、全角・漢数字、
  「9番の自販機」のような書き方など、抜け道を塞ぎきれない
- そのため、AI には根拠の行の選択(citations)だけを任せ、回答の文章はすべてサーバーで組み立てる。
  根拠外の自販機・価格が回答に入る経路がなくなる
- 代わりに、回答は決まった形(固定の前置き + 行の一覧)になり、AI の言い回しは使えない
