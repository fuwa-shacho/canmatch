# RAG評価セット（Issue #67）

## 評価の目的

10問（根拠のある質問7問、登録データでは答えられない質問3問）を固定し、同じ質問で検索と回答の正しさを別々に測定する。通常の質問画面、検索処理、生成処理は変更しない。

質問と期待商品名は`evals/rag-questions.json`に記載。期待商品名は既存のProductSeederから選んでいる。ただし、商品マスタへの登録だけでは不十分で、その商品を販売する自販機の情報が必要。

## 採点

- 検索（答えあり）: 正解商品名の根拠が最低1行取得されれば合格。
- 検索（答えなし）: 根拠が0行なら合格。
- 回答（答えあり）: citationが最低1行あり、選ばれたすべての行が正解商品かつ根拠内の組（自販機ID・商品ID・価格）に一致すれば合格。
- 回答（答えなし）: 根拠から何も選択していなければ合格。
- 失敗・タイムアウト: その質問の検索・回答を不合格として記録する。集計値を曖昧にしない。

この採点は、正解商品集合のうち**少なくとも1種類**を正しく見つけることを評価する。網羅率、回答商品の価格順、地理的距離、更新日の正しさは別の評価項目として扱う。

## 使い方

```bash
php artisan eval:rag
php artisan eval:rag --live --save=storage/app/rag-eval-result.json
```

引数なしは評価データの形を確認するだけで、Cloudflareの無料枠を使わない。`--live`は実際のCloudflare APIを呼ぶため、#64の`EvidenceRetriever`が統合された後に使用する。

本番ではなく開発DBで正解商品を販売する自販機が存在することを確認してから実行する。事前条件を満たさない場合は実行を中止し、0点として誤計上しない。結果には評価日時、RAGしきい値、モデル、指示文の版を残す。設定を変えた場合は同じ10問で再実行し、PR本文に結果を貼る。

外部サービスが呼ばれる実評価を通常の自動テストには入れない。Unit/Featureテストでは採点ロジックとデータ構造のみ確認する。

## 残る検証

- #64のマージ後、実際の`EvidenceRetriever`から根拠を取得してコマンドが動くことを確認。
- #66の質問画面が使う処理と、評価が使用する`EvidenceRetriever` / `AnswerGenerator` の設定を一致させる。
- 開発用の自販機データを用意し、実評価値を記録。結果は実測前に記載しない。
